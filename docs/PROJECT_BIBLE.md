## Vision & Mission
A trustworthy, bilingual (English + Marathi) hyperlocal civic and business directory platform originating in **Muktainagar, Maharashtra** and expanding into a regional multi-town network (including Bhusawal, Varangaon, Bodwad, Jalgaon, Pune/Maval) — moderated, free for residents to use, mobile-first, installable (PWA), and resilient to slow networks. *(Confirmed from product surfaces, geo subsystem, and multi-location architecture.)*

## Project Purpose
Make every legitimate local business, service, bus route, school, mess, and hostel findable, callable, and routable from one place. The directory exists because (a) Google Maps coverage of tier-2/tier-3 and rural India is patchy, (b) WhatsApp-forwarded info goes stale, and (c) residents and students want a single verified source of truth they can trust. **(Confirmed.)**

## Critical Workflows (high level — full detail in `WORKFLOWS.md`)

1. **Visitor browse & location selection** → Header Location Pill / CityPicker → `/:citySlug` Home/Shops → ShopDetail → Call/WA/Maps/Review (logged to `shop_engagement`).
2. **Listing request (multi-entity)** → `RequestListingModal` (`entity_type`: shop/mess/pg/school) → `shop_requests` (pending) → admin approve → real `shops`/`schools`/profile rows + image rename + duplicate-phone check.
3. **Daily menu & vacancy management** → `/my-shop` or Admin Directory → daily update for today's food menu or bed vacancies.
4. **Shop claim** → `ClaimShopModal` (proof upload) → `shop_claims` (rate-limited) → admin approve → `shop_owners` row + `shopkeeper` role.
5. **Owner edit** → `/my-shop` → `updateShopWithConcurrency` (optimistic lock on `updated_at`).
6. **Admin moderation** → `DirectoryInbox` (Requests/Claims/Owners/Assign sub-tabs).
7. **Category merge** → `CategoryMergeModal` (two-step, conflict-safe shop re-link).
8. **Banner serve** → `BannerSlot`/`BannerPopup` → 3-layer flag check → `is_active` + date range → Intersection Observer view tracking.

## Business Rules (the "why")

- **Moderation-first:** All listings staged in `shop_requests` before going live. Phone numbers drive real calls; spam = real-world harm.
- **Duplicate phone block:** Phone numbers are the de-facto primary key of a local business. Duplicates are caught at approval (cheaper than at submission, and the same number can legitimately be in 2 pending requests but only approved once).
- **Owner column guard:** DB-level BEFORE trigger blocks non-admins from changing `is_verified`, `is_active`, `slug`, `category_id` on `shops` — bypasses the frontend whitelist as a second gate.
- **Concurrency-safe shop edits:** Admin and owner can both edit the same shop. `WHERE id=$1 AND updated_at=$2` UPDATE prevents silent overwrites.
- **PII walling:** `profiles` SELECT is self/admin/owner-context only. Anon reads go through `profiles_public` view (id + full_name only). Proof images in `shop-images/claims/<user_id>/` protected via signed URLs and storage RLS.
- **Anon-safe writes via SECURITY DEFINER RPCs:** Banner view/click counters and engagement logging accept anon writes without exposing the underlying tables.
- **"Sponsored" labels are mandatory** in code — removing them requires a code change. The directory's editorial trust is the product.
- **Category merge preserves shops:** Re-link before delete; shops in both source and target collapse cleanly (no orphans, no dupes).
- **Image hygiene:** Multi-image and primary cover flows enforce WebP compression (max 1600px). Pending-deletions queue means old images aren't dropped from storage until the new save succeeds.

## Current Architecture Summary (high level — full detail in `ARCHITECTURE.md`)

- **Frontend:** React 18 + Vite 5 + TypeScript SPA. React Router v6 (path-prefixed town routes), TanStack Query v5 (2m staleTime, localStorage category persister), shadcn/Radix + Tailwind, lucide-react. Custom i18n provider, no global state library.
- **Backend:** External Supabase project (`fhlaqgzensagjangkpop.supabase.co`). PostgREST + Realtime + Storage + Auth + MCP Deno Edge Function (`/functions/v1/mcp`).
- **Auth:** Supabase email/password (no OAuth for users; OAuth 2.0 for MCP clients). Roles in `user_roles` checked via `has_role` SECURITY DEFINER.
- **Storage:** Four buckets — `shop-images` (shops + banners + claim proofs), `school-images` (admin write), `request-images` (public pre-approval submissions), `banner-images`.
- **Build & CI/CD:** Universal `npm run build` using standard `tsx` for `generate-sitemap.ts` and `prerender.ts`.
- **Hosting:** Vercel primary (`vercel.json` with SPA routing and prerendered clean URLs); Lovable Cloud compatible. Full migration runbook in `docs/VERCEL_MIGRATION_PLAN.md`.
